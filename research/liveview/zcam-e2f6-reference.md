## 為什麼放在這裡

fp 的 LCD 研究要回答「監看訊號在哪裡被截斷、要怎麼保留餘量」。Z CAM 用同一顆感光元件，
而且整條監看轉換是**明文 GLSL**，每一步都看得到，是現成可讀的參考實作，不需要從 ASIC 暫存器反推。

## Z CAM 的做法（ZLog2 錄影 → Rec.709 監看）

```
錄影 YUV(ZLog2) ─BT.709 矩陣→ RGB(0..1, log 域 clamp)
  → from_gamma：lin = (10^((V−0.385537)/0.3455) − 0.0064)/60      碼值 1.0 = lin 1.0
  → clamp 0..1 → invertCompress（減去 15/4096 的黑位 lift）
  → × 12.8（HLG 16.8 / PQ 23.2）
  → 3×3（顯示器 XYZ→RGB × ZLog2 原生→XYZ，CPU 先乘好）
  → 1024 點顯示表（每台機器的面板校正檔；沒有校正檔 = Rec.709 OETF）→ clamp → YUV
```

全程在 GPU 上用 float 運算。中間唯一的截斷是 log 域的 0..1，這不會丟掉場景資訊；
第一個真正會丟資訊的限幅是最後的顯示值 clamp。

## 跟 fp 研究直接相關的觀察

| 項目 | Z CAM | 對 fp 的意義 |
|---|---|---|
| 高光 | **硬切**，灰階以上 +3.65 檔（ZLog2 0.63）就到 255；沒有 roll-off | ZLog2 實際記錄到約 +7.3 檔，一半的高光在 LCD 上看不到。原廠也沒做我們目標中的「平滑高光壓縮」，所以這方面不能當標竿 |
| 中灰 | 18% 灰 → 顯示線性 0.083 → **64/255（25%）** | 故意壓暗約 1.1 檔來換高光空間；這只是單純的曝光偏移，不是曲線設計 |
| 色域 | 單一 3×3，**沒有色域壓縮**；超出 709 的顏色各通道分別 clamp | 飽和色也會在最後的 clamp 被切掉，而且是逐通道切，會造成色相偏移 |
| 白點 | 沒有做白點適應；原生白 xy (0.3184, 0.334) 直接顯示，中性灰偏暖（R>G>B） | — |
| 面板 | 每台機器有 `/tmp/nv/cali_display.gamma`（1024 點 ×3）加顯示色域矩陣，由 `CalcDislpayGammaCurve` 產生 | 跟 fp 研究「最後校正 LCD 的矩陣與顯示曲線」這一步的分層完全一樣：監看轉換和面板校正是兩個獨立的表 |
| 模式 | `monitor.image_prf`：0 關閉、1 SDR、2 HLG、3 PQ 1000、4 使用者 3D LUT | HLG/PQ 只換增益（16.8/23.2）和輸出曲線，前段共用 |

## 可以借用的

- **架構**：log 解碼 → 單一增益 → 一個合成矩陣 → 可替換的 1D 顯示表，順序乾淨，每一級都可以單獨驗證。
- **「黑位 lift 在解碼後扣掉」**：ZLog2 的黑不在碼值 0，而是在 0.162；Z CAM 先照公式解，再扣 15/4096。
- **HLG/PQ 共用前段**：只換 gain 和輸出曲線。

## 不要照抄的

- 硬切與逐通道 clamp。這正是 fp 研究想避免的「高光和飽和色提前變成一片」。

## 把 Z CAM 的 IMX410 CCM 套在 fp RAW 上的裁切比較（2026-09-24）

細節與數字：[`ZCAM_E2F6_FIRMWARE.md`](../../zcam_e2f6/notes/ZCAM_E2F6_FIRMWARE.md)「高光/暗部裁切比較」。

- **矩陣造成的提前高光裁切**：有彩度的顏色，SIGMA 中位數 +0.12 檔、Z CAM +0.23 檔（最多約半檔）。彩度越高，矩陣越早把某個通道推到 1。
- **感光元件飽和**：這張的白平衡下 G 最先飽和，R、B 還會繼續上升，所以不管用哪個矩陣，高光都會變洋紅。這是順序問題，**在套矩陣之前，要把白平衡後的三通道一起切在最先飽和的那個點**。
- **暗部**：負係數越大，暗部雜訊越容易變成負值被切成 0，平均值被抬高（這張是 R 被抬高，暗部偏紅）。Z CAM 的負值比例約是 SIGMA 的 1.6–2.3 倍。
- **結論**：Z CAM 的 CCM 對監看餘量沒有幫助；要保留餘量，應該用**彩度較低的監看矩陣**，或做**色域壓縮**，而不是換用別家的校正。

## 白平衡後先切在 G 飽和點再套矩陣：實測（2026-09-24）

模擬感光元件飽和（`_SDI5625` × 曝光，每個通道各自在 RAW 1.0 飽和）：
- 直接「白平衡 → 矩陣」：飽和高光出現**粉紅色帶**，彩度平均 4–9（SIGMA）、7–17（Z CAM），亮度也被拉低到 93–98。
- 「白平衡 → `min(cam, G 飽和點)` → 矩陣」：兩個矩陣都變成中性白（彩度 < 1），**差異也消失**。
- 代價：R、B 在 G 飽和之後的資訊（這張最多約 0.8 檔）直接丟掉；要保留這段，需要做高光重建，而不是 clamp。

## Z CAM 沒有 RAW 監看

LCD 永遠是 ISP 預覽 YUV + assitool shader。RAW 只能經 HDMI 送出（`OPMODE_RAW_SEND`：VI pipe dump → 塞進 VO 的 buffer → Atomos），此時 HDMI 不能顯示影像，監看工具會改畫在 LCD 上。這版也已經不能在機內錄 ZRAW。**fp 的 rawlive 在他們的程式碼裡沒有前例。**
